# Xpilot startup and parked identity

Use the owner's supplied logo for the software startup spinner, mici parked
home, large-screen parked header and moving screensaver. This is host UI
identity; it adds no vehicle behavior or plugin permission. The AGNOS boot
partition and onroad overlays are unchanged.

The original transparent PNG is stored byte-for-byte, SHA256
`7f06630cd0aaf4e3f7abfcd8f0b67b4e394ff57ea53dbe80b7b824a4acc2d78f`.
The UI renders its alpha silhouette in white with a cached shader and texture.
Generated redraw drafts were rejected and are not included. A specific Git
attribute keeps this startup asset in ordinary Git so it is available before
LFS resources are fetched.

Failure cases and geometry/draw/fallback checks were introduced before the
implementation in `tools/sp_tesla_e2e/branding_check.py`. Initial execution
failed because the required layout module did not exist. Final check passes
nine screen/status layouts, containment, drawing and missing-file fallback.
Native macOS offscreen rendering also produced inspected 2160x1080 and
536x240 previews. Existing local font/spinner assets are LFS pointers, so these
previews do not establish production font or spinner texture appearance.

Validation: generated Params/safety checks, pr_risk, all 15 host checks listed
in xpilot.yaml (including branding_check), store_e2e against the paired plugin
checkout, fork_pair_check and git diff --check: exit 0.
No firmware build is required or claimed.

Device follow-up: native GLES initially rejected the fragment-only shader due
to a version mismatch with the default vertex stage. A failing check was added
before the repair; both stages now explicitly use the application's shader
version. Repeated native rendering succeeded without shader link errors and
the exported device image shows the white logo, spinner and progress bar.
The six startup/mici/screensaver files were backed up and installed while fresh
device state confirmed offroad. The older device parked dashboard lacks the
glass-header implementation, so its screen.py was preserved rather than
installing unrelated UI changes. Activation evidence is recorded separately
under the private deployment directory. No road validation is claimed.
